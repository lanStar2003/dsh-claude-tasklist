# 复刻规格：Claude Code 桌面版「实时任务清单 + 下一步框」

本插件在 dsh（DeepSeek Harness）里复刻 Claude 桌面版 Code 页的两个功能：

1. **实时任务清单**：模型在工作时调用 `update_plan`，清单固定在本轮最新一条消息的下方，随工作推进实时更新。
2. **下一步框**：模型在一轮结束时调用一次 `wrap_up`，在本轮末尾画出总结，可附带一个问题和 1–2 个按钮，点按钮等于用户发出一条消息。

模型使用 dsh 会话当前的模型，插件本身不配置任何模型。

---

## 1. 行为规格（照 Claude 原版工具语义）

### 1.1 `update_plan`

| 参数 | 类型 | 含义 |
|---|---|---|
| `items` | `{content, status}[]`，1–12 项 | 整张清单按顺序给出，**整体替换**旧清单。`status` 为 `pending` / `in_progress` / `completed`。`content` 是不超过约 7 个词的祈使短语。 |
| `scope` | `first_task` / `new_task` / `continuation` | 有 `items` 时必填，说明这次请求对会话意味着什么。只记录，不影响画面。 |
| `advance` | `true` | 把当前 `in_progress` 一步标为完成，并把下一项 `pending` 设为 `in_progress`。最后一步之后不再有 pending，此时只完成当前步。 |
| `done` | `number[]`（从 1 开始） | 乱序完成：把这些序号标为完成。 |
| `start` | `number`（从 1 开始） | 乱序开始：把这一项设为 `in_progress`，原先进行中的步骤回到 `pending`（除非同一次调用里被 `done` 标成完成）。 |

规则：

- 首次调用必须带 `items`；没有清单时调用 `advance` / `done` / `start` 返回错误，让模型改正。
- 同一次调用里先应用 `items`，再应用 `done`，然后是 `start`，最后是 `advance`。
- 工作中应恰好有一项 `in_progress`；全部做完时没有任何一项处于进行中。插件不强制这一点，只在工具结果里提醒。
- 序号越界、`items` 为空或超过 12 项、`items` 缺 `scope`，都返回错误，清单保持原样。
- 工具结果与原版一致，内容很短：`Plan shown (N steps).`、`Plan updated: step K of N is in progress.`、`Plan updated: all N steps completed.`

### 1.2 `wrap_up`

| 参数 | 类型 | 含义 |
|---|---|---|
| `recap` | string，必填，≤300 字符 | 两三句话：现在什么已经成立或变了、进展到哪、还有什么没做或没验证。 |
| `ask` | string，≤100 字符 | 只在下一步要用户决定时给出。只问一个决定，不说理由、不列选项。 |
| `actions` | 1–2 个 `{label, message?}` | 回答 `ask` 的按钮。第一个是推荐项，画成主按钮。`label` 1–3 个词、≤24 字符；`message` ≤300 字符，省略时发送 `label`。 |
| `blocked` | boolean | 为 true 表示必须等用户回答才能继续，此时会话显示「需要您的输入」。 |

规则：

- 每轮最多一次。调用后清单里所有未完成的步骤自动打勾（原版："it also checks off the task list"），之后不再需要调用 `update_plan`。
- `ask` 和 `actions` 必须同时出现或同时省略。
- 工具结果告诉模型接下来做什么：
  - 有 `ask` 时：`Next-step box shown with your question. End your turn now; write no text after this call.`
  - 没有 `ask` 时：`Recap shown. Your closing message follows this call: answer the user in full.`
- 用户点按钮：按钮的 `message`（或 `label`）作为用户的下一条消息发出，下一步框随之进入"已回答"状态，按钮不能再点。
- 原版的应用动作按钮（commit / create_pr / merge 等）属于 Claude 桌面版自己的功能，dsh 里没有对应能力，所以不实现，只保留回复按钮。

### 1.3 展示位置

- 清单属于产生它的那一轮，画在**这一轮最后一条消息之后**，不在工具调用卡片里。
- 正在进行的一轮里，清单始终显示在最新一条消息的下方，并随 `update_plan` 实时更新。
  dsh 的对话流在本轮结束前没有「最新消息之后」的挂载点（`ChatFlow` 末尾只有运行状态行），
  所以进行中的清单放在输入框正上方的停靠区 `conversation.input.dock`。滚到底时它就在最新消息正下方。
- 一轮结束后，它的清单留在原位，保持最终状态（dsh 的 `conversation.chat.turnTail`）。
- 下一步框画在这一轮清单的下方。
- `update_plan` / `wrap_up` 的工具调用卡片不出现在对话记录里，它们只是记账用的。
- 重新打开会话、刷新页面后，清单和下一步框原样恢复。

### 1.4 系统提示词

插件向模型注入一段使用说明，内容改写自原版的 "Task list and wrap-up" 一节，去掉 dsh 没有的部分（另开会话、PR 自动修复等）：

- 凡是要改文件、或要运行不止一条命令的请求，先计划再动手：这一轮的第一个工具调用是 `update_plan`，给出完整计划，而且单独发出，下一条消息才开始执行。这一点与原版不同：原版让计划和第一个工具调用一起发出，但 dsh 会先显示正在生成的工具调用，看起来像边执行边列清单。
- 每完成一步，`advance: true` 和开始下一步的那个工具调用一起发出，让清单始终停在正在做的那一步。
- 代码模式（PTC 预设，只有 `run_code` 能直接调用）下，计划是一个单独的 `run_code`，程序里只有 `await tools.update_plan({...})`；之后每段开始新步骤的程序第一行是 `tools.update_plan({ advance: true })`，最后用 `tools.wrap_up(...)` 收尾。
- 计划变了或用户改了方向，重新发送整张清单，已做完的步骤保持完成；不要事后重写清单来描述做过的事。
- 维持恰好一项进行中；全部完成后没有进行中的项。
- 一轮工作结束时调用一次 `wrap_up`，然后再写收尾的话。有问题要问时，下一步框就是这一轮的结尾，调用之后不再写任何文字。
- 只回答一句话的问题、纯聊天，不需要清单也不需要 `wrap_up`。

### 1.5 语言

原版跟随用户的语言。本插件默认要求清单的每一步和下一步框的全部文字（总结、问题、按钮文字和按钮发送的话）都用简体中文（设置项 `language`，默认 `zh-CN`；`auto` 表示跟随用户）。要求写在工具说明和系统提示词里；中文时还在工具执行时检查：任何一段文字里没有汉字，就整次调用报错退回，模型改正后重发。检查只在执行时做，回放历史时不做，所以以前的英文清单照常恢复。

### 1.6 推进提醒

原版没有这一项。两种情况会提醒：

- 一轮里还没有清单，模型就调用了别的工具（包括 PTC 模式下的 `run_code`）：第一次工具调用之后提醒一次，请它需要多步时先列计划，只是查一下就直接回答时忽略。
- 某一轮有清单、还没 `wrap_up`、有步骤没做完，而且连续 3 个模型步骤（`remindAfterSteps`）没有调用 `update_plan` / `wrap_up` 时，插件在那一步的工具结果后面附一条提醒，点名还在进行中的那一步，请模型做完就 `advance`。之后每再过 3 步提醒一次；新的一轮重新计数。`remindAfterSteps: 0` 关掉这两种提醒。提醒是来源为 `tasklist` 的普通上下文消息，模型看得到，对话记录里不显示。
